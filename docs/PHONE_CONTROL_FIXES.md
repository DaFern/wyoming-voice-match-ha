# Phone pause/cancel safeguards — development only

## Report and evidence

During real Companion-app testing on 2026-11-05, the user said “pause learning”
at sample 3 and “cancel learning” at sample 4, but the flow advanced. The add-on
logged samples 3 and 4 as saved before a later cancellation paused the flow.
Treat that unfinished set as potentially contaminated; do not resume it for
acceptance testing. Its audio was not inspected or deleted during development.
No replacement voiceprint was generated by this four-sample session.

The detailed control logger was not enabled after the restart. The exact
transcriptions and the cause of those real misses are unknown. The old parser
accepted only exact stop strings after stripping a small set of punctuation;
commas, interior punctuation, repeated spacing and polite forms could miss it.
That is a reproducible parser weakness, not proof of the user's precise failure.

## Revised behaviour

- Consent remains a separate post-notice exact “start learning” turn. Positive
  consent is not widened by the new stop-command normalisation.
- “Pause learning” (also stop/no aliases) pauses and keeps unfinished recordings
  for a freshly consented resume. Before consent it starts no new learning.
- “Cancel learning” after consent requests deletion of only this unfinished
  session's recordings. It preserves the installed voiceprint, unrelated
  sessions/profiles and external backups. Deletion is not secure disk erasure.
- Before consent, cancellation says no learning started in this conversation.
  It does not delete an earlier paused session for which this conversation has
  not obtained a session capability; the response says those recordings remain.
- Stop/cancel recognition normalises Unicode punctuation and spacing and accepts
  a leading/trailing “please”. Ambiguous, repeated, negated or stop-like variants
  never authorise deletion. They discard the current clip and attempt a safe
  pause, preserving recordings. Notice-like playback, launch aliases and repeated
  consent phrases are also excluded from training once learning has begun.
- Automatic listening, varied prompts, saved-count advancement, rejection retry,
  original audio duration/format checks and no exact reading-phrase matching
  remain in place. No LLM or ordinary Assist commands execute in learning.

These guards cannot recover a stop command that Whisper transcribes as entirely
unrelated text. Real STT/endpointer/TTS behaviour is still an acceptance gate.
Do not describe the original real-phone bug as conclusively solved by fixtures.

## Backend boundary

The existing wire `cancel` operation remains a non-destructive pause for older
coordinators, automatic disconnect cleanup and the management page's correctly
labelled Pause button. The new phone cancellation uses a separate encrypted
`discard` operation with an explicit confirmation and the exact source/session
capability. It never falls back to broad profile cleanup.

The backend rechecks capability expiry, actor/profile ownership, pairing boot,
latest generation and the pending-session identifier under the runtime lock.
Every begin/resume, including management, invalidates older discard capabilities.
A delayed old token cannot remove a resumed generation even after that generation
pauses. Active processing and completed installations cannot be discarded.

Filesystem preflight rejects unsafe links and unexpected session files before
deleting anything. Staging hardlinks are matched by filesystem identity, not
filename alone. Only the selected session's WAV/part/generated-candidate files
and matching staging hardlinks are removed. Other session directories and the
installed voiceprint are outside this operation. Local storage is trusted; this
is not an atomic filesystem transaction against an adversarial concurrent writer.

Partial cleanup failure reports attention and blocks permits/new begins. A lost
discard reply is not automatically retried: subsequent phone turns only query
the bound receipt. Disconnect, changed chats and local expiry cannot silently
turn uncertain deletion into a successful pause/new begin. Unknown or expired
receipts require management attention rather than a claim that files were deleted.

## Deployment and real acceptance

Requires both the updated add-on backend and companion; a companion-only rollout
against an older peer cannot provide destructive cancellation. Unsupported
discard fails closed, reports unverified, and stops further phone sample uploads.
No release/version bump, commit, publication, live deployment, recording cleanup,
logger change or Core restart is included in this development task.

After separately approved deployment, verify fresh-session cancellation wording,
sample-phase pause with no count advance, fresh-consent resume, and sample-phase
cancel with deletion verified before starting a new clean set. Check both normal
and punctuation/polite control transcriptions. Close Assist immediately if a
control advances the count. The existing potentially contaminated recordings must
be dealt with only after explicit approval; do not silently reuse/delete them.

## Local validation — 2026-11-05

- Unit discovery: 168 ran, 164 passed and 4 skipped. This includes the real
  encrypted loopback bridge, pause/resume/discard semantics, unrelated-file and
  installed-voiceprint preservation, staging hardlinks, ownership/expiry checks,
  generation supersession, lock-wait rechecks, unsafe links, cleanup/metadata
  failures, uncertain-reply recovery and all guided phrases remaining readable.
- Native HA suite: 55 passed on HA 2026.10.0, including normalised/ambiguous
  controls, separate pause/discard behaviour and pre-consent wording. STT/backend
  boundaries are synthetic; DSP is stubbed and real FFmpeg is unavailable.
- Targeted Ruff passed on controller/diagnostics/bridge and phone/discard tests.
  Backend guided/voices lint findings were compared with HEAD: 8 and 1
  respectively, all pre-existing, with no new findings. No unrelated cleanup.
- Pending Python AST and diff whitespace checks passed.

Real Android, Whisper transcription/endpointer behaviour and TTS echo exclusion
remain unverified. The later passing native run followed correction of two stale
test expectations for the deliberately changed no-active-session wording.
